# Web の企画(ブランドの公式サイト + 製品ごとの販売ページ)

作成: 2026-10-04。利用者の指示(「ブランドの公式サイト」と「製品ごとの販売LP」)にもとづく。
**名前は仮**(ブランド名が決まったら差し替える)。**価格・販売プラットフォーム・特商法の表記は未定**(止まる対象。枠だけ用意)。

## 目的と、誰に何を伝えるか

| ページ | 目的 | 読む人 | いちばん伝えたいこと |
|---|---|---|---|
| ブランドの公式サイト | シリーズの考え方を示し、製品へ案内する | 録音・書類をクラウドに上げたくない個人事業主・会社員 | 「あなたの記録は、この端末の中で。買い切りで、ずっと手元に」 |
| 議事録の販売ページ | 試してもらい、買ってもらう | 会議・面談・取材の録音を文字にしたい人 | 「録音を、この端末の中で議事録に。話者・要確認・ToDo まで」 |

## ブランドの思想(The Taling. から引き継ぐもの)

- **途中を消さない**: 会議の「途中」(誰が何を言ったか、決まるまでの流れ)を、そのまま残す。
- **時間を奪わない**: 確認・修正を速く。通知や無限スクロールで引き止めない。
- **比べない・責めない**: 誤りがある前提で、直しやすくする(「確実」「完全」と言わない)。
- **手元に灯す**: データは端末の外に出さない。買い切りで、使い続けられる。
- 見た目は `core/brand/`(生成りの紙・灯りの琥珀・明朝の見出し)。他社(tranext など)の名前・配色・文言はまねない。

## サイトの構成

```
/                      ブランドの公式サイト
  ├ 考え方(なぜ端末の中で・買い切りなのか)
  ├ 製品一覧(議事録 / 今後の製品は「準備中」)
  ├ データの扱い(送らないもの・通信する場面の一覧)
  └ お問い合わせ(メールのみ)
/minutes/              議事録の販売ページ
  ├ ファーストビュー(一言・画面・無料で試す/購入)
  ├ できること(取り込み・録音 / 話者 / 確認と修正 / 議題・ToDo / 書き出し)
  ├ 端末の中で動く(送らないもの、通信の一覧)
  ├ 無料版と有料版(docs/plans.md の表)
  ├ 動作環境(macOS Apple Silicon / Windows 準備中、メモリの目安)
  ├ よくある質問
  └ 表記(名称・機能・価格は変更される場合があります、特商法・規約・返金は販売開始時)
/legal/                利用規約・プライバシー・特商法(販売開始時に作る。いまは「準備中」)
```

## 文言のルール(`checklists/copy-rules.md`)

- 使わない: 「完全」「確実」「100%」「安全」「法的に問題なし」「正確に文字起こし」。
- 必ず載せる: 「文字起こしには誤りが含まれます」「録音の同意を得る責任は利用者にあります」、通信する場面の一覧、
  「名称・機能・価格は変更される場合があります」(発売前)、買い切りの範囲(サポート期間・更新の範囲)、返金の条件(決まったら)。
- 数値は測った条件を添える(「M2 で、合成音声で」など)。最低ライン機の数値が出るまでは、速さを断定しない。
- 他社の名前を出して比べない(誤認・権利の問題)。

## 技術

- 静的な HTML/CSS(`web/`)。`core/brand/tokens.css` を共有し、アプリと同じ見た目にする。JavaScript はほぼ使わない(速く、追跡しない)。
- アクセス解析は、入れるとしてもクッキーを使わない方式(プライバシーの方針と矛盾させない)。いまは入れない。
- 公開先(独自ドメイン・ホスティング)は未定(利用者が決める。公開は止まる対象)。

## 公開(GitHub Pages)

準備だけ済んでいます。**利用者が有効化して実行するまで、何も公開されません。**

- 仕組み: `.github/workflows/pages.yml` が `web/` を `_site/` に組み立てる。`core/brand/tokens.css` を `_site/tokens.css` に同梱し、`site.css` の import を `tokens.css` に書き換える(プロジェクトサイトの `https://<ユーザー>.github.io/<リポジトリ>/` でも CSS が届くように。ローカル確認用の元ファイルは変えない)。`.nojekyll`、`404.html`、`robots.txt`(巡回を許可)も含む。
- いつ動くか: `web/**`・`core/brand/**`・ワークフロー自体の変更を `main` か `mac/verify` に push したとき、または手動実行(workflow_dispatch)。**公開(deploy)は `main` への push と手動実行のときだけ。** `mac/verify` への push は組み立ての確認のみ。
- 利用者がすること:
  1. リポジトリの Settings → Pages → Source を「GitHub Actions」にする。
  2. 公開してよいと判断したら、`main` に反映するか、Actions タブから pages を手動実行する。
- 要確認: 非公開(private)リポジトリで GitHub Pages を使うには有料プランが必要で、無料プランではリポジトリを公開(public)にする必要がある。どちらにするか確認してから有効化すること。
- 独自ドメインは後から設定できる(任意)。名前・ロゴ・アイコンは未確定のため入れていない。

1. 試作(`web/index.html`、`web/minutes/index.html`)— この文書と同時に作成。
2. アプリの画面のスクリーンショット(架空のデータ)を差し込む。

4. 検証済み(2026-10-04、ローカルの Chromium): リンク切れ・画像・CSS(ルート配下と `/localAIproduct/` 配下の両方)、コンソールのエラー、375px・1280px の横スクロール、見出しの順序、alt、`lang="ja"`、本文の文字色のコントラスト、HTML の文法(html-validate)。直したもの: 小さい字の色が薄い(コントラスト不足)、スマホ幅で製品のボタンがはみ出す、`legal/` への切れたリンク(準備中の間は文字だけにした)。サイトは暗い配色に対応していない(明るい配色のまま表示される。壊れてはいない)。
5. `legal/` を作ったら、フッターの文字をリンクに戻す。Windows 版は、実機で確認できるまで「準備中」のままにする。
