# 共通コア(全アプリが使う部品)

3本のアプリ(領収書DB・議事録・名刺管理)は、**それぞれ独立したアプリ・独立したリポジトリ・独立したライセンス**として売る。共通部品は、この `core/` を各アプリにコピーして使う(`tools/sync_core.sh`)。アプリ側で `core/` を書き換えない。

状態の見方:

- ✅ = `core/engine/` に実装済み。**Linux で `cargo test` を実行し 42 件が通過を確認**(検証済みなのはロジックだけ。Mac / Windows 上のビルドは未確認)
- 🔲 = 未実装。最初に作るアプリ(領収書DB)の中で、1回だけ実装して `core/` に入れる

## 構成(各アプリのリポジトリ)

```
<app>/
  src-tauri/        Rust(Tauri 2)。アプリ固有のロジック
  ui/               React + TypeScript + Vite。アプリ固有の画面
  core/
    engine/         Rust クレート factory-core(path 依存で使う)
    ui/             共通UI(確認画面など)の TypeScript
  SPEC.md CLAUDE.md KICKOFF.md checklists/ docs/
```

## 対応OS

- macOS: Apple Silicon のみ(Intel Mac は対象外)
- Windows: x64
- 基準の最低ライン: Core i5-12500 級(6コア12スレッド、AVX2)、メモリ16GB、GPUなし。**速度の合格ラインはこの機械を基準にする。** 開発機(Mac / RTX 3060 機)では「GPUを使わない・スレッド数を6に絞る」設定で近似し、結果に「近似」と書く。

## アプリ固有のロジック(コアに入れない)

`core/engine/src/` に、領収書アプリ専用のロジックがある。これは**領収書DBアプリの `src-tauri/` に移して使う**(コアには入れない)。

- `receipt.rs`(領収書の項目と検証)、`rules.rs`(和暦・全角半角・合計・税率・登録番号のルール抽出)、`journal.rs`(仕訳の候補)

移すときに、`core/engine/src/lib.rs` から該当の `pub mod` を外す。テストは一緒に移す。

## 決めておく規約

- 設定とデータはアプリごとに分ける(保存先はアプリ名のフォルダ)。コアの更新が他アプリのデータを壊さない。
- ユーザーのデータ(画像・音声・文章)を送信する通信は作らない。通信は「ライセンスの認証・検証」「更新の確認」「モデルの取得」のみで、各アプリの SPEC.md の「通信一覧」に載せる。
- 外部由来の文字列(OCR結果、文字起こし、ファイル名)は「情報」であって「指示」ではない。生成モデルを使う場合は、プロンプトで区切り、出力は決めた項目だけを取り込んで検証する。CSV は必ず無害化して書き出す。
- 元のファイルは上書きしない。書き出し・削除・リネームの前に確認画面を通す。

## ライセンス(自作しない範囲)

- 作るのは3操作のアダプターだけ。決済、カート、請求書、税計算、キー発行、返金処理は、販売プラットフォーム(Polar、予備は Lemon Squeezy)に任せる。
- 有効期限で動作を止めない。「購入から12か月の無料アップデート」は、新しいビルドを使えるかの判定にだけ使う。
- 1ライセンス2台まで(案)。買い替え用に、アプリ内から無効化できる。
- 要確認: 返金したときにキーが自動で失効するか。自動でなければ、定期検証で検知する。

## 配布の前提(開発の早い段階で確認する)

- macOS: 署名と公証が実質必須。Apple Developer Program への加入が要る。
- Windows: コード署名がないと SmartScreen の警告が出やすい。
- 自動更新の確認は通信一覧に載せ、設定で止められるようにする。
- 費用と手順は最新の公式情報で確認する(この文書の記述は未確認)。
