# サポート方針(買い切りの「範囲」を先に決める)

無期限の保守を約束しないために、販売前に決めて、LP・規約・販売ページに同じ文言で載せる。数字は例なので、自分の運用に合わせて決める。

| 項目 | 決めること | 例 |
|---|---|---|
| ライセンス | 動作の権利は無期限にするか | **無期限**。期限で動作を止めない(買い切りの信頼が崩れる) |
| 無料更新の期間 | いつまでのバージョンアップが購入に含まれるか | 購入から12か月。アプリのビルド日と購入日を比べて判定する |
| 期間後 | 保守のみ(OS対応・重大な不具合)か、有料の新版か | 既存のバージョンは使い続けられる。新しい機能は新版で |
| 対応OS | 公式に動作確認する範囲 | macOS(Apple Silicon)と Windows(x64)の、発売時点の最新と1つ前 |
| 台数 | 1つのライセンスで使える端末数 | 2台まで(買い替えのために、自分で無効化できるようにする) |
| 窓口 | 受け付ける手段 | メールのみ。返信は営業日の目安を書く |
| 対象外 | 受けない相談 | 個別の使い方の指導、AIの出力内容の誤りの責任 |
| 返金 | 条件と期限 | 購入から7日以内。販売プラットフォームの規定がある場合はそれに従う |
| 終了 | 販売や保守をやめる場合の扱い | 事前に告知し、既存の購入者には最終版を提供 |

運用のコツ

- 問い合わせの8割は同じ質問になる。FAQを先に書き、返信テンプレートを作る。
- アプリが増えるほど窓口は1人に集まる。窓口は1つ(メール)に絞る。
- 「更新の権利」の期限とライセンスの期限を混ぜない。販売プラットフォームのライセンス有効期限は、動作を止めるために使わない。
