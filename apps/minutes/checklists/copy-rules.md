# 表現のルール(アプリ内・販売ページ・LP・note記事)

## 使わない表現

| 避ける | 理由 | 代わりの書き方 |
|---|---|---|
| 「電帳法に完全対応」「インボイス対応済み」 | 法令適合の断定になる | 「帳簿づくりの補助として、仕訳の候補を作ります」 |
| 「確実に」「100%」「間違いなし」 | AIの出力は誤りを含む | 「確認・修正してから確定できます」 |
| 「法的に問題ありません」「税務署に通ります」 | 助言の断定になる | 「最終的な判断はご自身または専門家で」 |
| 「安全」「完全に匿名」 | 保証になる | 「処理は端末の中で行い、入力を送信しません」 |
| 「◯◯公認」「◯◯対応」(他社名) | 提携の誤認 | 「◯◯に取り込める形式で書き出し」(事実のみ) |
| 利用者の声・レビュー風の文章 | 作り物の評判になる | 実際に届いたものだけを、許可を得て掲載 |

## 必ず載せるもの

- 開発中・発売前のLPには、「名称・機能・価格は変更される場合があります」。
- アプリには、SPEC.md の「注意書き」(AIの出力は確認が必要、など)。
- 通信する場面の一覧(SPEC.md の「通信一覧」と同じ内容)。
- 買い切りの範囲(サポート期間と、含まれる更新の範囲)。`support-policy.md` を参照。
- 返金の条件。

## 「端末の中で処理」と書いてよい条件

- 画像・音声・文章を、実際に外部へ送っていない(通信ログで確認済み)。
- 例外の通信(認証・更新確認・モデル取得)を、別に明記している。
