# 議事録(仮称)— SPEC

slug: `minutes` ／ 作業の前に `CLAUDE.md` と `core/README.md` を読むこと。

## 概要

- 一言: 会議や面談の録音のノイズを抑えて、日本語の文章にする。録音データは端末の外に出ない。
- 対象: 会議・面談・講義の録音を文字にしたい人。録音をクラウドに上げたくない人。
- 注意書き(アプリとLPに必ず載せる): 文字起こしには誤りが含まれます。重要な箇所は音声で確認してください。録音の同意を得る責任は利用者にあります。
- 対応OS: macOS(Apple Silicon)・Windows(x64)。最低ライン: Core i5-12500級・メモリ16GB・GPUなし。
- 販売: 外部の販売プラットフォーム(買い切り)。決済・税・キー発行は自作しない。
- **競合に注意**: 文字起こしの既存サービスは多い。このアプリの差別化は「ノイズ除去と一体」「完全ローカル・買い切り」「用語辞書」「確認画面で音声を聞きながら直せる」。競合調査は本スペックの外で別に行う(未実施)。

## ユーザーの流れ

1. 録音ファイル(m4a / mp3 / wav など)を取り込む。
2. ノイズ除去 → 文字起こしが進む(進捗表示。閉じても続く)。
3. 確認画面で、音声を再生しながら文字を直す。話者のラベルを手動で付ける。
4. 議事録として書き出す。過去の議事録を全文検索する。

## スコープ(2週間で出す範囲)

- [x] 取り込み: m4a / mp3 / wav / mp4(音声のみ取り出し)。長い録音(1〜2時間)に対応(ストリームで 16kHz に変換してディスクに置き、メモリに全体を載せない。**2時間の実録音での確認は未実施**)
- [x] ノイズ除去(本アプリ内、RNNoise の Rust 移植 nnnoiseless)。オン/オフを選べる。除去後の音声を書き出すオプション
- [x] 音声区間の検出(無音の飛ばし)と、長い録音の分割処理(最長30秒、手前10秒の一番静かな所で切る。エネルギーによる簡易判定)
- [x] 日本語の文字起こし(時刻つきの区間)。whisper.cpp + Whisper large-v3-turbo(MIT)
- [x] 確認画面: 区間をクリックするとその位置から再生、文字の修正、区間の結合・分割、話者ラベルの手動付与、信頼度が低い区間に印、元に戻す
- [x] 用語辞書: 利用者が登録した語(専門用語・固有名詞)を、文字起こし後に正しい表記へ置換(誤りやすい読みと正しい表記のペアで登録)。正しい表記は Whisper の initial prompt(認識のヒント)にも渡す
- [x] 議事録のメタ情報: タイトル、日付、参加者(自由記入のテキスト)
- [x] 書き出し: Markdown、テキスト、SRT(字幕形式)。LaTeX や Word は後から追加できる形で書き出し部分を分けておく(`export.rs`。今回は作らない)
- [x] 議事録の全文検索(SQLite FTS5 trigram)
- [~] 設定: 通信一覧の表示、更新確認のオン/オフ、データの全削除、音声を残すかどうか、ノイズ除去の既定。ライセンスの有効化は、通信しない署名つきキーで実装した(2026-10-05。画面は未接続。本番の鍵は未作成)
- [x] 進捗・中断・再開(`core/jobs`)。長い録音の途中で閉じても、続きの区間から処理できる(区間ごとに保存)

凡例: `[x]` = 実装し `cargo test`(と画面はモックでの Playwright)で確認済み、`[~]` = 一部。2026-10-04、Mac(M2)で実装。**Windows でのビルド、最低ライン機での速度、実会議の録音での精度は未確認。**

## データモデル(SQLite)

```
meetings(id, title, held_on, participants_text, audio_path, duration_sec, created_at, updated_at)
segments(id, meeting_id, idx, start_ms, end_ms, speaker, text, confidence, edited)
segments_fts(text)   -- FTS5。日本語の部分一致は trigram を試す
glossary(id, wrong, right)
jobs(id, kind, state, progress, error, payload_json)
```

- 文字起こしのモデルはアプリに同梱する(2026-10-04 決定。`docs/legal-notices.md`)。
- 音声はアプリのデータフォルダにコピーして保持する(元のファイルは上書きしない)。保持しない設定(文字だけ残す)も用意する。
- 長い録音は、無音で区切った区間(数十秒)ごとに処理し、区間単位で結果を保存する(再開のため)。

### スパイクの暫定結果と選定(2026-10-03。詳細は `docs/spike-results.md`、`docs/licenses.md`)

- **状態: 暫定。文字起こしは実測できていない**(実行環境がモデル配布元に接続できなかった)。ノイズ除去のみ実測。
- ノイズ除去: RNNoise(BSD-3、RTF 約 0.066)と DeepFilterNet3(MIT/Apache、RTF 約 0.035)を 4 スレッド・GPUなしで実測し、どちらも速度は合格ライン内。**暫定案: RNNoise を既定(軽い・依存が小さい)、DFN3 は選択式を検討**。優劣と、文字起こしへの影響は未測定。DFN3 は無音(0)が続く入力で極端に遅くなるため前処理が要る。メモリは区間処理が前提。
- 文字起こし: 候補は A. kotoba-whisper v2.0 / B. Whisper large-v3-turbo(または small) / C. ReazonSpeech 系(sherpa-onnx)。**暫定の方針: ライセンスが一次情報で確認できた B(MIT)を基準にし、A・C はライセンス確認と実測の後で比較**。数値は未取得。
- ffmpeg: 環境のものは GPL ビルド。同梱するなら LGPL 構成か Rust のデコーダに替える(要確認)。

### 採用(2026-10-04、Mac M2 での実測と実装による。数値は `docs/spike-results.md` の 4・5)

| 部品 | 採用 | 理由 |
|---|---|---|
| 殻 | Tauri 2 + React + TypeScript + Vite | Mac で起動・実文字起こしまで確認(`docs/ui/mac-real-transcription.png`)。Windows は未確認 |
| 音声の読み込み | symphonia 0.5(Rust。wav / mp3 / aac・m4a / mp4 / flac / ogg) | ffmpeg(GPL ビルド)を同梱しなくて済む。MPL-2.0 の表記は要確認 |
| ノイズ除去 | nnnoiseless(RNNoise の Rust 移植、BSD-3) | スパイクの RNNoise と同等(エアコン雑音で SI-SDR 5.1 → 10.6 dB)。依存が小さい。DFN3 は見送り |
| 文字起こし | whisper.cpp(whisper-rs)+ Whisper large-v3-turbo の q5_0 量子化(574MB、MIT) | 3 候補中で誤り率が最も低く(合成音声で約 4%)、ライセンスが一次情報で MIT。kotoba-whisper は誤り率が高く(約 26〜29%)、ReazonSpeech 系はデータ由来の条件が未解決 |
| 区間の分割 | エネルギーによる簡易判定(最長 30 秒) | 追加のモデル不要。Silero VAD は見送り(必要なら後で) |

## スパイク(最初の2〜3日。合格しなければ止まって報告)

テストセット: 会議・面談を想定した録音 5〜10本(各5〜30分)。雑音の種類(エアコン、キーボード、マイクが遠い、複数人の同時発話)を混ぜる。**個人情報を含まない台本を自作して読み上げた録音**を使う。正解の書き起こしを人が付けて `testset/` に置く。

| 指標 | 合格ライン(提案値・未検証) |
|---|---|
| ノイズ除去 | 10分の録音を、再生時間の半分以内で処理 |
| 文字起こし | 30分の録音を、再生時間と同程度以内(目標)。「一括で放置して終われば許容」の線は実測を見て決める |
| 日本語の誤り率(文字単位) | 合格ラインは実測を見て決める。**まず3つ以内の候補モデルで測り、結果を表にして報告する** |
| ピークメモリ | 4GB以内 |
| インストール容量 | 2GB以内を目安(モデルを任意取得にする案も含めて検討) |

- 測定は、GPUを使わない設定・スレッド数6〜12で行う。Mac(Apple Silicon)は基準にしない。
- 合格しない場合は、(a) 小さいモデルにする、(b) 一括処理に限る(進捗と中断・再開を前提に)、(c) 機能の縮小、(d) 推奨スペックの引き上げ、の順に提案して**止まる**。

## データの保存と削除

- 保存場所: OSのアプリデータフォルダ内の、アプリ専用フォルダ(音声のコピー、SQLite、ログ)。
- 削除: 議事録ごとに、音声と文字をまとめて削除できる。設定の「全データを削除」で全部消える。
- 暗号化: 初版はアプリ内の暗号化を行わない。OS のディスク暗号化の案内を設定画面に載せる。SQLCipher の採用は「要確認」。
- 録音の同意: 取り込み時に「録音の同意を得る責任は利用者にあります」と表示する(毎回ではなく初回と設定画面)。
