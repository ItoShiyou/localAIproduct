# 音声アプリの4画面

2026-10-05: ユーザーが承認したパステル調の4案を、一つのアプリ内の目的別画面として採用。

- 読む: 全文を読む。補助操作は折りたたみ、再生は下部。
- 聞いて直す: 波形と再生操作を本文の前に置き、文字・話者を編集。
- 議事録を仕上げる: 議題・決定事項・ToDoと元の発言を並べる。要約下書きはこの画面内で開く。
- 一文ずつ直す: 一文のみを表示し、前後移動と区間再生で確認。

一覧は開閉式。録音の停止操作は一覧を閉じても表示する。取り込み・録音・辞書・設定・検索・書き出しの既存処理は保持する。
配色は音声アプリだけの `ui/src/calm.css` に定義し、他アプリの共有ブランド設定は変更しない。
本番版のライセンス制限は変更していない。要約のモデルやProライセンスがない場合も手動で議事録を編集できる。

## 今回の確認

TypeScript/Viteビルドと録音キューの2テストが成功。
ローカルブラウザのモックAPIで4画面移動、一文の修正保存、前後移動、議事録入力保持、確定後の書き出し有効化を確認。
ブラウザ実行時エラーなし。Mac用unsignedアプリを再ビルド。
実マイク・実ファイルの新UIでの認識、販売用署名・公証は今回のUI確認には含めない。

`ui/e2e/workspaces.mjs` は新画面用の回帰テスト。今回は同等の操作をアプリ内ブラウザで確認し、このスクリプト自体は未実行。
既存の `flow.mjs` / `free.mjs` / `license.mjs` は旧画面のタブラベルと常時表示サイドバーを前提にしているため、新画面に合わせた移行が必要。
