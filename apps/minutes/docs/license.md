# ライセンス(オフラインで検証する方式)

作成: 2026-10-05。利用者(販売者)の指示: 「研究者や医学系分野など機密性が高いところでの利用を想定している。ライセンス認証がなくてもよい形の買い切り(オフライン版)も作ってほしい」。
**価格・販売名・販売文面はここでは決めない**(利用者が後で決める)。オンライン認証(標準版向け)は作っていない。差し込み口だけ残した(末尾)。

## しくみ(やさしい説明)

- ライセンスは「購入者の名前などを書いた短い文書に、販売者だけが持つ鍵で**電子署名**をしたもの」。アプリには、署名を確かめるための**公開鍵**だけが入っている。
- アプリは署名を**端末の中だけで**確かめる。認証サーバーは無く、通信は一切しない。機内モードでも、インターネットの無い部屋でも有効になる。
- 購入者には、文字列(`MNT1-…`)または `.license` ファイルを渡す。アプリの設定で貼り付け(またはファイルを選ぶ)と、有料版になり、購入者の名前が画面に出る。
- 文書を書き換えると署名が合わなくなり、無効になる。販売者の鍵が無いと、新しい署名は作れない。

### 中身(署名の対象)

`{ v:1, id(乱数16桁), licensee(購入者名・組織名), edition("pro_offline" | "pro"), issued(発行日), features(["pro","summary"]), machine(端末コード、または null) }`

| 項目 | 意味 |
|---|---|
| `edition: pro_offline` | **オフライン版**。ネットワークを使う機能を常に止める(切り替え不可) |
| `edition: pro` | 通常の有料版。通信を止めるかは利用者の設定(「ネットワークを使わない」) |
| `features` | `pro` が無いキーは無効。`summary` が無ければ要約は使えない(その他の有料機能は使える) |
| `machine` | 端末に固定する場合の端末コード。空なら、どの端末でも使える |

### 暗号の部品

- 署名: Ed25519(`ed25519-dalek` 2.x、BSD-3-Clause)。キーの文字列は 署名 64 バイト + JSON を Base32 にして、6 文字ずつダッシュで区切ったもの。購入者名が日本語のとき、キーは約 500 文字になる(メールに貼れる長さ。`.license` ファイルでも渡せる)。
- 実装: `src-tauri/src/license.rs`(検証)、`src-tauri/examples/license_issuer.rs`(発行)。core の `license`(販売プラットフォームに問い合わせる方式)は使っていない・変更していない。

## 端末への固定(選べる。既定は固定しない)

| | 固定しない(既定) | 端末に固定 |
|---|---|---|
| 渡し方 | キーを送るだけ | 購入者が「端末コード」を先にメールで知らせる → 発行 → キーを送る(往復が1回増える) |
| 別の端末への入れ替え | 自由にできる(買い替え・複数台) | できない。端末が変わったら再発行(購入者に連絡が要る) |
| 他人への譲渡・共有 | 防げない。画面に出る**購入者名**が抑止になる(研究室・病院の名前が出るため、見知らぬ人に渡しにくい) | その端末以外では動かない |
| 向いている売り方 | 機密性が高く、手続きを増やしたくない顧客。オフライン版 | 台数で売りたい場合 |

- 端末コード: OS の端末 ID(macOS は IOPlatformUUID、Windows は MachineGuid)を、塩つきの SHA-256 にして先頭 10 バイトを `ABCD-EFGH-IJKL-MNOP` の形にしたもの(元の ID は外に出ない)。設定画面に端末コードの表示・コピーボタンを接続済み。
- 端末コードが変わりうる場面: OS の入れ直し・ディスク交換・仮想マシンの複製。固定したキーは、そのとき無効になる(理由は画面に出る)。

## 販売者の作業(はじめに1回)

> 鍵の生成・保管は**販売者本人が行う**(CLAUDE.md の「止まって確認すること」)。リポジトリには、秘密鍵も本番用の公開鍵も入っていない。

1. 発行用のコマンドを作る(リポジトリのルートで):
   `cargo build --release --example license_issuer --no-default-features --manifest-path apps/minutes/src-tauri/Cargo.toml`
   → `apps/minutes/src-tauri/target/release/examples/license_issuer`
2. 鍵を作る: `license_issuer keygen`
   - 秘密鍵は `~/.config/minutes-license/issuer.key`(権限 600)に保存される。リポジトリの中の場所はコマンドが拒否する。`.gitignore` にも `*.key` `*.license` がある。
   - 画面に出る**公開鍵**(16進 64 文字)を、`src-tauri/src/license.rs` の `PRODUCTION_PUBLIC_KEY_HEX` に貼り、アプリをビルドし直す。**貼るまで、配布用のビルドで有効になるライセンスは無い**(安全側)。
3. **秘密鍵のバックアップ(必須)**: USB メモリなどオフラインの媒体に2か所以上。パスワードマネージャーの暗号化メモでもよい。
   - **失くすと、新しいライセンスを発行できない**(すでに発行したものは使い続けられる。新規・再発行ができなくなる)。公開鍵を替えたアプリを配り直すことになり、既存の購入者には新しいキーを再発行しないと更新版が使えない。
   - **漏れると、誰でもライセンスを発行できる**。その場合は新しい鍵に替え、公開鍵を入れ直したアプリを配り、購入者にキーを再発行するしかない。クラウドの共有フォルダ・メール・チャットに置かない。
4. 発行の台帳を作る(表計算でよい): `id`・購入者・発行日・販売プラットフォームの注文番号・版・端末の固定の有無。返金・失効・再発行のときに `id` が要る。

## 販売者の作業(購入のたび)

- 端末に固定しない: `license_issuer issue --licensee "◯◯大学 △△研究室" --edition pro_offline --out ◯◯.license`
- 端末に固定する: 購入者から端末コードをもらい、`--machine ABCD-EFGH-IJKL-MNOP` を付ける。
- `--edition` は `pro_offline`(オフライン版)か `pro`(通常)。`--features` の既定は `pro,summary`。
- 出力された `.license` ファイルか、画面に出るキーの文字列を購入者に渡す(販売プラットフォームの商品の配信、メール、郵送の紙・USB でもよい)。
- 確かめる: `license_issuer verify ◯◯.license`(署名と中身を表示)。
- 開発用: `--dev` を付けると開発用の鍵で署名する(デバッグビルドのアプリだけが受け入れる。製品では使えない)。

## 購入者の使い方(アプリ)

設定の「ライセンス」で、キーを貼る、または `.license` ファイルを選ぶ。名前と版が表示され、有料版になる。外すこともできる(外すと無料版に戻る)。
アプリの「全データを削除」を押しても、**ライセンスは消えない**(購入したものなので。消すのは「ライセンスを外す」だけ)。OS の入れ直しやアプリの入れ直しのあとは、キーをもう一度入れる(購入者がキーを保管しておく)。

## 決めてほしいこと

1. **端末に固定するか**(上の表)。既定は固定しない。顧客ごとに選ぶ運用も可能(コマンドの `--machine` の有無だけ)。
2. **オフライン版だけにするか、通常版も作るか**。いまのコードは、`pro_offline` キーなら通信を止め、`pro` キーなら止めない(利用者の設定で止められる)。「すべての有料版をオフライン方式で売る」なら、`pro_offline` だけを発行すればよい。オフライン版の値付け(標準版より少し高く、など)は販売者が決める。
3. **無料版のお試しをオフライン版にも付けるか**(購入前に試す方法)。いまは、キーが無い間は無料版(累計60分)で動く。
4. onnxruntime のファイルの扱い(下の節)。
5. 返金のときの運用(下の節)。

## 失効・返金(オフラインでできないこと)

- **配ったキーを、通信で無効にすることはできない。** 返金してもキーは動き続ける。
- 対策(いまの実装):
  - 画面に購入者名を出す(共有の抑止)。
  - アプリの更新で、特定の `id` を無効にできる(`license.rs` の `REVOKED_IDS`)。更新を入れない端末では無効にならない。台帳の `id` から探して載せる。
  - 端末に固定すれば、他の端末では動かない。
- 返金の運用の例: 返金の条件に「ライセンスの使用をやめること」を入れる(販売ページ・利用規約。文面は販売者が決める)。必要なら次の更新で `REVOKED_IDS` に載せる。オフライン版は、更新を入れない運用の顧客もいるため、確実な失効はできない。

## ネットワークを使わない設定とオフライン版

- 設定 `offline_mode`(「ネットワークを使わない」)が true、または `pro_offline` のライセンスが入っているとき、次を止める: 文字起こしのモデルの取得(`download_model`)、要約のモデルの取得(`download_summary_model`)。理由は「ネットワークを使わない設定のため、取得できません。ファイルから取り込んでください」。設定画面の通信一覧は、すべて「止めている」表示になる。
- アプリの通信の棚卸し(2026-10-05、コードの検索による): 通信するコードは、core の `model_manager`(ureq)による上の2つのモデル取得だけ。更新の確認は設定の項目だけで、実際の通信は実装されていない。ライセンスの検証は通信しない(アプリの通信一覧にあった、将来用の「ライセンス認証・検証」の行は削除した)。画面は同梱のファイルだけを読む。**実際に通信を切った状態での確認と、通信ログの確認は未実施**(SPEC の受け入れ基準)。
- `tauri.conf.json` の CSP は設定済み。配布版の `connect-src` は Tauri IPC のみに制限し、開発版では Vite のローカル接続も許可する。Rust側のモデル取得はこの制限とは別に、オフライン設定を確認する。通信監視を含む通し確認は別途必要。
- **要約のモデルをファイルから取り込む**(`import_summary_model`): 通信のない現場では、別のパソコンで取得した `Qwen3-4B-Instruct-2507-Q4_K_M.gguf`(2,497,281,120 バイト)を USB で持ち込む。アプリがコピーしながら SHA-256 を確かめ、想定(`3605803b…e597`)と違えば取り込まない。
  - ファイルの入手元: `https://huggingface.co/unsloth/Qwen3-4B-Instruct-2507-GGUF/resolve/main/Qwen3-4B-Instruct-2507-Q4_K_M.gguf`。または、オフライン版の購入者へ USB・ダウンロードで配る(Apache-2.0 の再配布。`legal/qwen3-model-LICENSE.txt` を添える)。
  - 文字起こしのモデルとノイズ除去・話者判別のモデルは、もともとアプリに同梱している。

## onnxruntime が作るファイル(話者の判別)

- 事実(2026-10-04 の Mac での観察): onnxruntime は、読み込み時に `~/Library/Application Support/Microsoft/DeveloperTools/.onnxruntime/` に、端末の識別子(`deviceid`、36 バイト)と小さなデータベース(`onnxruntime.db` ほか)を作る。バイナリの文字列に "Collector URL is not set, no upload." があり、20 秒間の `lsof` で接続は無かった。送信はしない見込みだが、**止める公式の手段は確認できていない**(`with_telemetry(false)` では止まらなかった)。
- 対策(実装済み、2026-10-05): onnxruntime の読み込みと最初のセッションの作成の間だけ、環境変数 `HOME` を、アプリのデータフォルダの中の `ort-home/` に向ける(`diarize.rs` の `EnvSwap`)。
  - **Mac での確認**: `HOME` を向けた状態では、識別子とデータベースは `ort-home/Library/Application Support/Microsoft/DeveloperTools/.onnxruntime/` に作られ、利用者の本来のフォルダのファイルの更新時刻は変わらなかった(読み込みのあとに `HOME` を戻して推論を実行した場合も同じ)。
  - ファイルは消えない(アプリのデータフォルダの中に残る。「全データを削除」で消える)。機密の現場でも、利用者の他のフォルダに識別子が残らない。
  - **Windows は未確認**(`USERPROFILE` `HOME` `LOCALAPPDATA` `APPDATA` を同様に向けている。実機で、別の場所に作られていないか確認が要る)。環境変数の差し替えは、話者の判別のモデルを読み込む間(`OnnxEmbedder::new`、最初に使うときの1回)だけ、プロセス全体に影響する。その間に他のスレッドが `HOME` を読むと一時的にアプリ専用フォルダが見えうる(無料版の使った量の記録の場所の計算は起動時に済んでいるため、影響しない見込みだが、実機での確認は未実施)。
  - すでに作られた古いファイル(前の版を使ったことのある端末)は、アプリからは消していない。手で消せるが、他の Microsoft 製ツールと共有するフォルダなので、アプリは触らない方針。
- 判断してほしいこと: これで足りるか。足りなければ、onnxruntime を自前でビルド(テレメトリ無効のオプション)する方法がある(手間が大きい)。話者の判別を使わない設定にすれば、onnxruntime は読み込まれない。

## 外部とのつながり(将来のオンライン認証)

- いまの出口は `license.rs` の `LicenseInfo` と、`commands.rs` の `reload_license`(版を決める1か所)。オンライン認証を足すときは、販売プラットフォームの結果から `LicenseInfo` を作る入口を `reload_license` に足す(core の `LicenseBackend` を使う)。オフライン検証のキーはそのまま残せる。
- 通信を足すときは、先に SPEC の通信一覧に載せる(CLAUDE.md)。

## 画面に必要なコマンドと型(画面の作り直しのあとに接続)

`src-tauri/src/tauri_glue.rs`(登録は `lib.rs`)。

| コマンド | 引数 | 戻り値 |
|---|---|---|
| `license_status` | なし | `LicenseStatusDto` |
| `install_license` | `text`(キーまたは .license の中身) | `LicenseStatusDto`(失敗は日本語のエラー文) |
| `install_license_file` | `path` | `LicenseStatusDto` |
| `pick_and_install_license` | なし(OS のダイアログ) | `LicenseStatusDto` または `null`(取り消し) |
| `remove_license` | なし | `LicenseStatusDto` |
| `machine_code` | なし | `string` または `null` |
| `import_summary_model` | `path` | `SummaryStatusDto`(終わるまで返らない。進み具合は `summary_status` の `downloading` と `downloaded` / `size`) |
| `pick_and_import_summary_model` | なし | `SummaryStatusDto` または `null` |
| `set_flag` | `key: "offline_mode"`, `on` | `SettingsDto`(`offlineMode` と `offlineForced` が増えた) |

- `LicenseStatusDto` = `{ valid, info: { id, licensee, edition, issued, features[], machineBound, offline, dev } | null, error: string | null, machineCode: string | null, tier: "free" | "pro", networkDisabled }`。`error` は「保存してあるキーが無効」のときの理由(別の端末用など)。
- `SettingsDto` の追加: `offlineMode`(通信を止めている)、`offlineForced`(オフライン版のため切り替え不可)。`network[]` は止めている間 `enabled: false`。
- 要約のモデルを取得中のボタン(`download_summary_model`)は、`settings.offlineMode` が true なら押せない表示にし、代わりに「ファイルから取り込む」を出す(押しても Rust 側が拒否する)。
- エラー文(日本語)は、そのまま表示してよい。形式・新しい形式・署名・端末・失効・機能なし・公開鍵なし(配布用のビルドに公開鍵が未設定)の7種類。

## 保存の場所と、環境変数

- ライセンス: アプリのデータフォルダの `license.key`(macOS: `~/Library/Application Support/dev.localaiproduct.minutes/`)。「全データを削除」でも残る。
- 開発: **デバッグビルドだけ**、ライセンスが無いとき環境変数 `MINUTES_TIER`(pro / free)で版を決める(未指定は有料版)。**配布用のビルドは環境変数を無視する**(2026-10-05 以前は、配布用でも `MINUTES_TIER=pro` で有料版にできた)。開発用の鍵(`DEV_SEED`、公開してよい)の署名もデバッグビルドだけが受け入れる。配布用のビルドを手元で有料版にするには、自分用のライセンスを発行して入れる(`tools/run-pro.command` は、ライセンスファイルを入れて起動する形に変えた)。
- 無料版の使った量の記録(`plan.rs` の Ledger)と、無料版の制限は変えていない。
- テスト: `cargo test --lib`(署名の正しい/別の鍵/書き換え、形式エラー、端末の固定と不一致、版と機能、失効、配布用のビルドで環境変数・開発用の鍵が効かない、オフラインでの取得の拒否、全データ削除でのライセンスの保持、要約モデルの取り込みでのハッシュ照合)。
