# スパイク結果(名刺管理)

**先に読むこと**

- 測定環境: クラウドの Linux 仮想マシン(**4 vCPU**、GPUなし)。基準の最低ライン(Core i5-12500 級、6コア12スレッド)とは**機種もコア数も違う**ので、時間は「近似」。Mac・Windows は**何も測っていない**。
- テストセットは**架空・合成**(`testset/`、Pillow で描いた画像50枚。実際の紙・撮影・実在の名刺ではない)。**実名刺での精度は未確定。** 合成画像は、OCRに有利(文字が整っている)な面と、不利な面(縦書きの描き方が実物と違う可能性)の両方がある。どちらに偏るかは分からない。
- ルールは、このテストセットの実OCR出力を見たあとで直した(後述)。**同じ50枚で直して同じ50枚で測っているので、数字は楽観的**(過学習の可能性)。
- OCR: `core::ocr` の `PpOcr`(検出 PP-OCRv4 + 認識 日本語 v3 を主、中国語 v4 を併用)。モデルは receipt-db のスパイクと同じファイル(`docs/licenses.md`)。**日本語モデルの出所は未確認のため、製品には同梱しない扱い。**
- 数値は捏造していない。測れなかったものは「未実測」と書く。

## 3. 何が原因か・何を直したか

1. **縦書き**: 以前は縦書き8枚で氏名・会社・役職が 0 だった。`core::ocr` の縦書き改善(`core` に取り込み済み)のあとで、氏名 8/8、電話 8/8 まで改善した。会社・役職・郵便番号・住所は縦書きでまだ 2/8 程度。
2. **ひらがな・漢字の1文字の読み違い**(日本語 v3): 会社名の完全一致を落とす最大の原因。ルールでは直せない(確認画面で打ち替える前提)。
3. ルール側で直したもの(実OCRの出力を見て):
   - OCRが落とした空白(「青木遥」「物流企画室係長」)、「〒」の読み違い(「テ」「元」「T」)、メール途中の空白と `://` の崩れ、「(株)」の開きかっこ落ち。
   - ハイフンなしの電話、カタカナ氏名(中黒入り)、法人格のない社名(事業を表す語で終わる行。弱い根拠として「要確認」の印が付く)、2行に折り返された社名。
4. 以上の修正は、このテストセットを見ながら行ったので、**過学習の可能性が高い**。実名刺で効くかは未確認。

## 4. ルール抽出だけの結果(OCRを通さない手書きのOCR出力もどき、25枚)

`testset/cards/*.ocr.json`(OCRを通さず手で書いた行データ)で、ルールだけを測った結果。**OCRの誤りを含まない**ので、上の実OCRの結果とは別物として読む。

- 想定内の13枚は全項目が一致。「難しい」12枚のうち、不一致が残るのは 12(OCRが `.` を `,` に誤認識した想定)と 25(縦書きで文字ごとに空白)の2枚。以前の不一致のうち 19(法人格なし)、21(カタカナ氏名)、22(ハイフンなし電話)、24(2行社名)、23(`@` の前後の空白)は、ルールを足して一致するようになった(これらは足す前から「既知の限界」として記録していたもので、足したあとは過学習の可能性がある)。
- 実行: `cd src-tauri && cargo test`(`tests/testset.rs` で固定)。

## 5. 未実測・未実施

| 項目 | 理由 |
|---|---|
| Mac(Apple Silicon)・Windows でのビルド・速度・onnxruntime の読み込み | この環境は Linux のみ |
| Core i5-12500 級(6コア12スレッド)での時間、スレッド6〜12 | 実機なし |
| 実際の名刺(撮影、影、装飾フォント、斜め)での精度 | 実データは使わない方針。合成画像のみ。装飾フォントは「別のフォントで描いた」程度で、実際の装飾書体は含まない |
| 縦書きの実画像 | 合成の縦書きだけ(上の1) |
| 別のOCR(OS標準、PP-OCRv5、Tesseract)との比較 | 今回は PpOcr のみ。Tesseract は receipt-db の測定で数字の精度が足りなかった |
| 50枚を超える枚数、複数面(表裏)の紐づけ精度 | 未実施 |

## 6. 提案(止まって確認)

会社名とメールが合格ラインに届いていない。SPEC.md の手順どおり、次を提案する(実行はしていない)。

1. (c)機能の縮小: 会社名・ふりがなは「読み取り結果を候補として出し、確認画面で打ち替える」前提にし、合格ラインの対象を確認後の項目にするか、会社名の完全一致を目標から外す。確認画面は実装済み(`ui/`)。
2. (b)日本語認識モデルの更新(PP-OCRv5 など)。出所とライセンスの確認が先。ひらがなの読み違いが主因なので、効く可能性が高い。
3. (a)メールは、ドメインを会社名・URLと突き合わせる補正の余地がある(例: URLの `hinata-kobo.example.com` と同じドメインなら採用)。ただし過学習に注意。
4. 実際の名刺(個人情報を伏せたもの)20〜30枚の提供を受けて、同じ手順で再測定する。
