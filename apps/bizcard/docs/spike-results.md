# スパイク結果(名刺管理)

**先に読むこと**

- 測定環境: クラウドの Linux 仮想マシン(**4 vCPU**、GPUなし)。基準の最低ライン(Core i5-12500 級、6コア12スレッド)とは**機種もコア数も違う**ので、時間は「近似」。Mac・Windows は**何も測っていない**。
- テストセットは**架空・合成**(`testset/`、Pillow で描いた画像50枚。実際の紙・撮影・実在の名刺ではない)。**実名刺での精度は未確定。** 合成画像は、OCRに有利(文字が整っている)な面と、不利な面(縦書きの描き方が実物と違う可能性)の両方がある。どちらに偏るかは分からない。
- ルールは、このテストセットの実OCR出力を見たあとで直した(後述)。**同じ50枚で直して同じ50枚で測っているので、数字は楽観的**(過学習の可能性)。
- OCR: `core::ocr` の `PpOcr`(検出 PP-OCRv4 + 認識 日本語 v3 を主、中国語 v4 を併用)。モデルは receipt-db のスパイクと同じファイル(`docs/licenses.md`)。**日本語モデルの出所は未確認のため、製品には同梱しない扱い。**
- 数値は捏造していない。測れなかったものは「未実測」と書く。

## 3. 何が原因か(実測で見えたこと)

1. **縦書きが読めない(8枚で氏名・会社・役職が 0)。** 縦書きの検出領域を水平に回して読むため、正立のまま縦に積まれた日本語の文字が、横倒しの文字として認識に渡されていると推測される。画像の縦書きの描き方(英数字の連続は90度回転、全角は正立)は、実際の縦書き名刺に近いつもりだが、実物との差は未検証。**これは `core::ocr::ppocr` 側の挙動で、`core/` は変更しない決まりのため、「要確認」に書いた**(縦書き領域を「1文字ずつ切り出して横に並べる」処理が要る見込み)。
2. **ひらがな・漢字の1文字の読み違い**(日本語 v3): 「ひ→び」「こ→ニ」「そ→て」など。会社名の完全一致を落とす最大の原因。確認画面で直す前提だが、合格ラインは完全一致で測っている。
3. **OCRが空白を落とす**: 「青木遥」「物流企画室係長」。氏名は空白なしの2〜5字の漢字も候補にし、部署と役職がつながった語は分けるようにルールを直した(修正の前後で、部署 33→37、役職 34→38、氏名 38→40)。
4. **「〒」の読み違い**(「テ」「元」「T」「干」): 郵便番号の前の1文字を許すようにして、郵便番号 28→45、住所 24→30。
5. **メールの途中の空白**(「example. com」「kobayashi @tsubaki」)や `://` の崩れ: 空白を詰める処理を足した。
6. **法人格のない社名**(「サンプル商事」)、**2行に折り返された社名**: ルールでは拾えない(架空データで既知の限界として固定済み)。

`testset/cards/*.ocr.json`(OCRを通さず手で書いた行データ)で、ルールだけを測った結果。これは**OCRの誤りを含まない**ので、上の実OCRの結果とは別物として読む。

## 5. 未実測・未実施

| 項目 | 理由 |
|---|---|
| Mac(Apple Silicon)・Windows でのビルド・速度・onnxruntime の読み込み | この環境は Linux のみ |
| Core i5-12500 級(6コア12スレッド)での時間、スレッド6〜12 | 実機なし |
| 実際の名刺(撮影、影、装飾フォント、斜め)での精度 | 実データは使わない方針。合成画像のみ。装飾フォントは「別のフォントで描いた」程度で、実際の装飾書体は含まない |
| 縦書きの実画像 | 合成の縦書きだけ(上の1) |
| 別のOCR(OS標準、PP-OCRv5、Tesseract)との比較 | 今回は PpOcr のみ。Tesseract は receipt-db の測定で数字の精度が足りなかった |
| 50枚を超える枚数、複数面(表裏)の紐づけ精度 | 未実施 |

## 6. 提案(止まって確認)

SPEC.md の手順どおり、合格ライン未達のため次を提案する。実行はしていない。

1. (a)ルールの拡充 — 効果が見込めるもの: ハイフンなし電話、カタカナ氏名、法人格のない社名(語彙の追加は過学習になりやすいので、実OCRの出力を見て優先順位を決める)。
2. (b)別のOCR/モデル — 縦書き用の処理(`core::ocr` 側)、日本語の認識モデルの更新(PP-OCRv5 など。出所とライセンスの確認が先)。
3. (c)機能の縮小 — 氏名・会社は確認画面での手入力を主にし、OCRはメール・電話・URL・郵便番号を主に補助する。SPEC.md の「確認画面を通す」方針とは矛盾しない。
4. 実際の名刺(個人情報を伏せたもの)20〜30枚の提供を受けて、同じ手順で再測定する。
