# 名刺管理(仮称)— SPEC

slug: `bizcard` ／ 作業の前に `CLAUDE.md` と `core/README.md` を読むこと。

## 概要

- 一言: 名刺の写真を取り込むと連絡先データベースになり、「この人、誰だっけ」を思い出せる記録を残せる。名刺は端末の外に出ない。
- 対象: 名刺を多く受け取る個人事業主・フリーランス・営業職の人。
- 注意書き(アプリとLPに必ず載せる): 読み取り結果は確認が前提です。相手の情報をアプリが自動で集めることはありません。
- 対応OS: macOS(Apple Silicon)・Windows(x64)。最低ライン: Core i5-12500級・メモリ16GB・GPUなし。
- 販売: 外部の販売プラットフォーム(買い切り)。決済・税・キー発行は自作しない。
- **競合に注意**: 既存の名刺管理アプリ(クラウド型を含む)は多い。差別化は「他人の個人情報を端末の外に出さない」「買い切り」「『誰だっけ』の記録が中心」。競合調査は本スペックの外で別に行う(未実施)。

## 最重要の設計方針(「この人、誰だっけ」)

名刺は、受け取った直後は覚えていても、数週間後に「この人、誰だっけ」となる。このアプリの価値は読み取りの精度より、**あとで思い出せる記録**にある。

- 取り込んだ直後に、「会った日・場所・きっかけ・話した内容」をすばやく残せる入力欄を出す(スキップできる)。
- 検索結果と詳細画面には、**名刺の画像と、自分のメモを大きく**表示する。
- 1つの検索窓で、氏名・会社・役職・メモ・タグ・場所のすべてを探せる。
- 相手のSNS・公開情報は、**アプリが自動で集めない**。利用者がメモ欄に自分で書く、またはコピペして残す。アプリは外部サイトを検索・取得しない。

## ユーザーの流れ

1. 名刺の写真(表・裏)をドラッグして取り込む(複数可、フォルダ可)。
2. 読み取りが進む。確認画面で、画像と読み取り結果を並べて見て、直して「確定」。
3. 確定時に「会った日・場所・きっかけ・メモ・タグ」を残す(任意)。
4. 検索窓で探す。「誰だっけ」と思ったら、検索して画像とメモを見る。必要なときにCSVで書き出す。

## スコープ(2週間で出す範囲)

- [ ] 取り込み: JPEG / PNG / PDF、フォルダ。1人につき表・裏の複数画像を紐づけられる。失敗したファイルは飛ばして続行。同一画像(SHA-256)の重複は取り込まない
- [ ] OCR(`core` の `ocr`)で、氏名、ふりがな(あれば)、会社、部署、役職、メール、電話、携帯、郵便番号、住所、URL を読み取る
- [ ] (ロジックと架空データのテストのみ実装済み。取り込み・OCR接続・画面は未実装。`src-tauri/src/extract.rs`) ルール抽出: メール・電話・郵便番号・URL は正規表現。会社は「株式会社」「有限会社」「合同会社」「Inc.」等の語。役職は語彙(部長・課長・代表取締役 等)。氏名は、文字の大きさと位置(OCRの位置情報)と語彙から候補を出す。日本語と英語の名刺の両方に対応。**生成モデルは使わない**(初版)
- [ ] 確認画面(`core/ui`): 画像と並べて表示、項目ごとに修正、信頼度が低い項目に印、一括確定、元に戻す。確定するまで連絡先として保存されない
- [ ] (ロジックとテストのみ実装済み。画面は未実装。`src-tauri/src/dedup.rs`) 重複の検知: メールが同じ、または氏名と会社が同じ人を「同じ人かもしれません」と提示し、統合するかを確認する(自動で統合しない)
- [ ] 「誰だっけ」の記録: 会った日、場所、きっかけ、メモ、タグ。**メモは複数追加でき、日付つきの履歴**になる(再会したときに追記)
- [ ] 一覧と検索(SQLite FTS5)。最近追加した順、会った日の順、会社別、タグ別
- [ ] (CSVのロジックとテストのみ実装済み。`src-tauri/src/csv_export.rs`。画面・vCard は未実装) 書き出し: CSV(UTF-8 BOM付き / Shift_JIS の選択、セルの無害化)。vCard 3.0 は余力があれば
- [ ] 設定: 通信一覧の表示、更新確認のオン/オフ、データの全削除、ライセンスの有効化
- [ ] 進捗・中断・再開(`core/jobs`)

## データモデル(SQLite)

```
people(id, name, name_kana, company, department, title, email, phone, mobile, postal_code, address, url,
       status, field_confidence_json, created_at, updated_at)
  -- status: 'draft' | 'confirmed'
card_images(id, person_id, side, sha256 UNIQUE, stored_path, imported_at)
encounters(id, person_id, met_on, place, how_met, memo, created_at)  -- 会った日・場所・きっかけ・メモ(履歴)
tags(id, name UNIQUE), person_tags(person_id, tag_id)
people_fts(name, name_kana, company, department, title, memo_all, place_all, tags_all)  -- FTS5(trigram を試す)
jobs(id, kind, state, progress, error, payload_json)
```

- 画像はアプリのデータフォルダにコピーして保持する(元のファイルは上書きしない)。
- 個人情報なので、ログに氏名・メール・電話を書かない。

## スパイク(最初の2日。合格しなければ止まって報告)

テストセット: 名刺 50枚(**架空の名刺を自作**する。実在の他人の名刺をテストに使う場合は個人情報をマスクする)。横書き・縦書き・英語・装飾フォント・斜め撮影・裏面(英語表記)を混ぜる。正解の項目を人が付けて `testset/` に置く。

| 指標 | 合格ライン(提案値・未検証) |
|---|---|
| 名刺1枚(OCRから抽出まで) | 3秒以内(最低ライン相当) |
| メール・電話の正答率 | 95%以上 |
| 会社名・氏名の正答率 | 85%以上(確認画面で直せる前提で、まず測る) |
| ピークメモリ | 4GB以内 |
| インストール容量 | 2GB以内を目安 |

- 測定は、GPUを使わない設定・スレッド数6〜12で行う。Mac(Apple Silicon)は基準にしない。
- 合格しない場合は、(a) ルールの拡充、(b) 別のOCR、(c) 機能の縮小(氏名と会社は手入力を主にする等)、の順に提案して**止まる**。

## 通信一覧

ユーザーのデータ(名刺画像・連絡先・メモ)を送る通信はありません。アプリは外部サイトを検索・取得しません。

| 目的 | 送信先 | 送る内容 | 止められるか |
|---|---|---|---|
| ライセンス認証・検証 | 販売プラットフォームのAPI(core 経由) | ライセンスキー、端末の識別名 | 不可 |
| 更新の確認 | (core) | アプリのバージョン | 設定で可 |
| モデルの取得(必要なときのみ) | (core) | モデル名 | 操作時のみ |

## データの保存と削除

- 保存場所: OSのアプリデータフォルダ内の、アプリ専用フォルダ(名刺画像のコピー、SQLite、ログ)。
- 削除: 1人ずつ(画像・メモを含めて)削除できる。設定の「全データを削除」で全部消える。
- 暗号化: 初版はアプリ内の暗号化を行わない。OS のディスク暗号化(BitLocker / FileVault)の案内を設定画面に載せる。SQLCipher の採用は「要確認」。**他人の個人情報を扱うため、この判断は発売前に必ず行う。**
- 書き出し(CSV)は、利用者が自分で管理する。書き出し時に「個人情報を含むファイルです」と表示する。
