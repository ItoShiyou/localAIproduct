# マイグレーションの進め方(案)

- 1ファイル1段階: `NNNN_説明.sql`。**追記のみ**で、出したあとの番号のファイルは書き換えない。
- 現在のバージョンは `PRAGMA user_version` で持つ。各ファイルの最後で `PRAGMA user_version = N;` を設定する。
- 適用は、トランザクション内で `user_version < N` のファイルを番号順に実行する。途中で失敗したら全体をロールバックする。
- 適用の前に、DBファイルのコピーを同じフォルダに残す(利用者の名刺データを失わないため)。コピーは端末の外に出さない。
- 新しいバージョンのDBを古いアプリで開いたら、書き込まずにエラーにする(`user_version` が自分より大きい場合)。
- 実行する側(`core` の `db`)は未実装。このSQLは「案」で、`core` の `db` が確定したら、その規約に合わせて見直す(要確認)。
- テスト: `src-tauri/tests/schema.rs` が、空のDBに適用して、外部キーの連鎖削除・全文検索の更新・下書きが検索に出ないことを確認する。
